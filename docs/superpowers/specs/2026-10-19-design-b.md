# APSlop Design B — 仕様

- 日付: 2026-10-19
- 画面: `docs/superpowers/wireframes/d/`(23 画面。2026-10-19 に Design B(`b/`)として「画面 OK」で確定。2026-10-20 に上の帯だけ
  Design E として選び直し、採用案のフォルダが `d/` になった。`b/` は Git の履歴にある)
- 位置づけ: 現行の Web UI(旧 Design A、`web/src/app`)を Design B へ段階的に置き換える。増分ごとに出荷する。

## Design B の方針(A からの変更点)

1. **訪問者用と開発者用を分ける。** 訪問者はアプリを見てインストールする(Apps / Install on your phone)。
   開発者はリポジトリ・PR・AI 生成を扱う(ヘッダー "APSlop Developers"、Dashboard / Repositories / New app / ← Store)。
2. **UI 文言を英語に統一する。**
3. **AI の変更は差分を確認してから PR にする。** AI が作った変更はすぐ GitHub に送らず、差分・PR のタイトルと説明を
   見せ、利用者が "Create pull request" を押したときに初めてブランチ・コミット・PR を作る。
4. **不足していた操作を足す。** ログインが必要なときの案内、Issue の詳細とコメント、アプリの設定(ストア掲載の一言、削除)。

## 増分 1: AI の変更を差分で確認してから PR を作る

### 利用者から見た流れ

1. リポジトリの "AI に依頼" タブ(増分 2 で "Create PR with AI" ボタンに置き換え)を開くと、`repo-ai` の画面。
   見出し "Create PR with AI"、説明文、複数行の入力欄、"Generate changes" ボタン、補足 "At least 5 characters. Takes 1–3 minutes."。
   ログインしていなければ入力欄の代わりにログインを促す一文。
2. "Generate changes" を押すと生成中の表示(ボタンが "Generating… (1–3 min)" になり無効化)。完了すると `repo-ai-review` へ移る。
   失敗したら同じ画面にエラーを出し、入力は残す。
3. `repo-ai-review`: 見出し "Create PR with AI — review changes"、"Nothing has been sent to GitHub yet. ..."、
   "Your request" カード(依頼文と "Edit request")、"Files changed (N)  +A −D"、ファイルごとの差分(Modified / Added / Deleted)、
   "Pull request" カード(Title と Description は AI の案が入っていて編集可、"Create pull request" / "Regenerate" / "Discard")。
4. "Create pull request" → 利用者の GitHub アカウントでブランチ・コミット・PR を作り、PR の詳細画面へ移る。
5. "Regenerate" → 同じ依頼文でもう一度生成し、新しい確認画面へ移る(前の案は破棄扱い)。
6. "Discard" → 案を破棄し、`repo-ai` へ戻る。
7. "Edit request" → 依頼文が入った状態の `repo-ai` へ戻る。
8. Dashboard の AI 履歴で、確認待ちの案は確認画面へのリンクになる。

### 決めたこと(見た目に出ない)

- 案はサーバーの DB(`Generation`)に保存する(ページを再読み込みしても失われない)。保存するのは PR のタイトル・説明・ブランチ名と、
  変更ファイルごとの変更前/変更後の内容、生成時点の基準コミット。
- PR のブランチは生成時点の基準コミットから切る(確認中に main が進んでも、AI が見ていない変更を巻き戻さない)。
- 確認画面と PR 作成は案を作った本人だけが使える(他人の案は 404)。
- `Generation.status`: PENDING → READY(確認待ち)→ DONE(PR 作成済み)/ DISCARDED / FAILED。
- 差分はサーバーで変更前/変更後から unified diff を作り、既存の差分表示部品で描く。
- PR 本文の末尾の注記は英語: `_Created by APSlop AI at the request of @<login>._`

### 追加(2026-10-19): AI の選択(Claude / DeepSeek)

利用者の要望で、「Create PR with AI」で使う AI を選べるようにする。

- `repo-ai` の入力欄の下に "Model" の選択欄。選択肢は "Claude (<ANTHROPIC_MODEL>)" と "DeepSeek V4.1 Flash"。
  サーバーにキーが設定されていない AI は "— not set up" を付けて選べない状態で並べる。既定は使える最初の AI。
- `repo-ai-review` の "Your request" カードに "Generated by <AI の名前>"。"Regenerate" は同じ AI で作り直す。
  "Edit request" で戻ると、依頼文と AI の選択が元のまま入っている。
- 決めたこと(見た目に出ない):
  - DeepSeek は公式 API の Anthropic 互換エンドポイント(`https://api.deepseek.com/anthropic`、モデル `deepseek-flash`
    = DeepSeek-V4.1-Flash-1017)を Anthropic SDK で呼ぶ。重みが約 510 GB あり、このマシンでの自前運用はしない。
  - 互換エンドポイントは `output_config.format`(構造化出力)を無視するため、DeepSeek では結果を `submit_result` ツールの
    呼び出しとして受け取り、zod で検証する。DeepSeek は既定で思考モードで、思考モードは強制の `tool_choice`
    (`tool` / `any`)を 400 で拒否するため、`tool_choice: {type: "auto"}` と system の指示で呼び出させる。
    ツールを呼ばず本文に同じ JSON を書いた場合(コードフェンス付きも)も受け付ける。Claude は従来どおり構造化出力。
  - 生成に使ったモデル名は `Generation.model` に保存し、そこから表示名と Regenerate の AI を決める。
  - 新規アプリの生成(`/new`)は Claude のまま。

### 増分 1 で変えないもの

- ヘッダー、リポジトリのタブ、他の画面の文言(増分 2 以降)。

## 増分 2: ヘッダーの訪問者/開発者分離と英語化、リポジトリの帯

### 利用者から見た流れ

1. トップ(`/`)とアプリのページ(`/apps/*`)は訪問者用ヘッダー(User Mode): "APSlop"、"Apps"、"Install on your phone"
   (トップのインストール案内へ移動)、右に "Developer Mode" のスイッチ(オフ)と "Sign in with GitHub"(ログイン中は
   アイコン・ログイン名・"Sign out")。スイッチを押すと Developer Mode へ(ログイン中は Dashboard、未ログインは Repositories)。
2. Dashboard / Repositories / New app とリポジトリ配下は開発者用ヘッダー(Developer Mode): "APSlop Developers"、
   "Dashboard"、"Repositories"、"New app"、右に "Developer Mode" のスイッチ(オン)とアカウント。スイッチを押すと
   User Mode(トップ)へ戻る。
   - 受け入れで変えた(2026-10-20): 太字だけでは今いる場所が分かりづらい → 今いる場所のリンクの下にオレンジの線
     (リポジトリのタブと同じ印)。"For developers →" / "← Store" の文字リンクはボタンと分からない → 縁のある
     切り替えにし、呼び名を User Mode / Developer Mode にした。形は案 C〜G(ボタン 1 つ、2 つ並び、スイッチ、
     ロゴ横のメニュー、上のタブ)からテストユーザーが E(スイッチ)を選んだ。
3. トップ・Dashboard・Repositories・リポジトリの Code / ファイル / フォルダ / Issues / Pull requests を英語にする
   (文言は `wireframes/d` のとおり)。日時も英語("3 days ago"、"Sep 12, 14:02")。フッターも英語。
4. リポジトリの帯: "Open on GitHub ↗" と緑の "Create PR with AI" ボタン。タブは Code / Pull requests N / Issues N /
   Releases / Settings。"AI に依頼" タブはなくなり、Pull requests 一覧の下に "New pull requests are made with
   “Create PR with AI” (top right)."。
5. Settings タブはアプリの持ち主にだけ出る(他人が URL を開くと 404)。この増分では "Store listing" を表示のみ:
   一言(Summary)、アプリ名、アイコン、説明(README.md へのリンク)、"These come from the app itself..." と
   "Create PR with AI"。一言の編集とアプリの削除は増分 4。
6. Dashboard の My apps: アプリ名はリポジトリへ、右に状態("Published v0.1.1" / "Draft" / "Failed")と "Settings"。
   AI history: 種類("New app" / "PR")、状態("Done" / "Running" / "Ready to review" / "Discarded" / "Failed")、日時。

### 決めたこと(見た目に出ない)

- ヘッダーの出し分けはパスで決める(`/dashboard`・`/repos`・`/new` 配下が開発者用、それ以外は訪問者用)。
  開発者用の場所で起きたエラーや 404 は開発者用ヘッダーのまま(移動先を失わないため)。
- Issues と Pull requests の件数は GitHub GraphQL で別々に数える(REST の `open_issues_count` は両者の合計)。
  リポジトリ一覧も GraphQL 1 回(100 件ごとにページ送り)で件数込みで取る。
- "Download the store app" はストアアプリの配布場所がまだないため、`NEXT_PUBLIC_STORE_APP_URL` が設定されたときだけ出す。
- 英語化しない(増分 5): New app、アプリのページ、Pull Request の詳細、Releases、エラー/404 画面。

## 増分 3: ログインが必要なときの案内、Issue の詳細

### 利用者から見た流れ

1. ログインしていないと使えない画面(Dashboard、New app、Create PR with AI の確認画面、Settings)は、GitHub の
   ログイン画面へいきなり飛ばさず `sign-in-required` の案内を出す: "Sign in to continue"、説明文、"Sign in with GitHub"。
   ログインすると、その画面に戻る。
2. 画面の一部だけがログインを要るとき(Create PR with AI の入力、New issue、Issue のコメント、PR のレビュー、Releases の作成)は、
   その場所に小さな案内("Sign in to continue. ..." と "Sign in with GitHub")を出す。上の帯の "Sign in with GitHub" も、
   押した画面に戻る。
3. Issues 一覧の題を押すと、このサイトの中の Issue の詳細(`issue-detail`)を開く: 題と番号、Open / Closed、
   "<login> opened this issue 2 days ago · 1 comment"、"Open on GitHub ↗"、本文、コメント、"Add a comment" の欄と
   "Comment" / "Close issue"(閉じていれば "Reopen issue")/ "Create PR with AI"、"Actions are performed as your GitHub account."。
4. Issue の "Create PR with AI" は、依頼の欄に "Fix issue #N: <題>" と本文が入った状態で Create PR with AI を開く。

### 決めたこと(見た目に出ない)

- ログイン後の戻り先はフォームの隠し欄で渡し、このサイトのパス(`/` で始まり `//` や `\` を含まない)だけを許す。
- コメントと閉じる・開き直すは利用者のトークンで GitHub に送る(権限は GitHub が判断し、断られたら文を出す)。
- GitHub は Issue と PR に通し番号を振るので、Issue の詳細で PR の番号を開くと PR の詳細へ移す。

## 増分 4: アプリの設定(ストアに出す一言、削除)

### 利用者から見た流れ

1. 持ち主が Settings タブを開くと、"Store listing" の一番上が "Summary (one line, shown in the store)" の入力欄と
   "Save" になる。80 文字まで、1 行。"Save" はいまの一言から変えたときだけ押せる。保存すると
   "Saved. The store now shows this summary."(未公開なら "... once the app is published.")が出て、リポジトリの帯の説明も変わる。
2. 下の "Danger zone" の "Delete app…" を押すと、その場に確認が開く: インストール済みの人は使い続けられるが更新は届かないこと、
   コード・Issue・PR・リリースはリポジトリごと消えること、"To confirm, type <リポジトリ名> below."。名前を正しく打つと
   赤い "Delete this app" が押せる("Cancel" で閉じる)。
3. 削除すると Dashboard に移り、"<アプリ名> was deleted. ..." が出る。My apps から消え、ストアからも消える。

### 決めたこと(見た目に出ない)

- ストアは公開のたびに GitHub のリポジトリの説明を一言として読むので、一言の正本はリポジトリの説明にする。
  保存はリポジトリの説明 → アプリの記録 → ストア(公開済みのとき)の順。ストアだけ失敗したら、次の公開で追いつく旨を出す。
- 削除はストア → リポジトリ → アプリの記録の順。ストアが断れば何も変わらない。リポジトリが消せなければ、アプリは
  Draft に戻して残し、もう一度削除できる(どの段も繰り返して安全)。
- リポジトリの説明の変更と削除はサーバー用トークンで行う(ログイン時の権限に `delete_repo` を足さない)。持ち主かどうかは
  このサイトの記録で確かめ、持ち主でなければ存在しないときと同じ 404 を返す。
- ストアのサーバーに `PUT /apps/{package}/summary` と `DELETE /apps/{package}` を足した。削除は metadata と repo・archive の
  APK を消して `fdroid update` する。パッケージごとの署名鍵は残す。

### 受け入れで見つかった不具合(増分 4)

- New app の "コードを生成する" が常に Claude を使い、このサーバーの Claude の鍵が通らず失敗した。New app にも
  Create PR with AI と同じ "Model" の選択を置き、最初は前回うまくいった AI(鍵があるもの)を選んでおく。両方の画面で同じ。
  鍵が断られたときの文は、どの AI が使えないかと、"Choose another Model" を示す。
- New app の "リポジトリを作成" が "Resource not accessible by personal access token"(git/trees)で失敗した。サーバー用トークンに
  Workflows の権限がなく、雛形の `.github/workflows/` を含むコミットを作れなかった(手順書から権限が漏れていた)。
  手順書に Workflows (RW) を足し、失敗したときは途中まで作ったリポジトリを消して、何が足りないかを英語で示すようにした。
  名前の重複は、このサイトの記録だけでなく GitHub のリポジトリも見て避ける(`-2` を付ける)。

## 増分 5: 残りの画面の英語化

### 利用者から見た流れ

1. New app(`new-input`): "New app"、説明文、入力欄、例のボタン 3 つ(押すと英語の依頼文が入る)、"Model"、"Generate code" と
   "At least 10 characters. Takes 1–3 minutes."。"Model" は増分 4 の受け入れで足したもの(Create PR with AI と同じ位置)。
2. 生成結果(`new-review`): "New app — review"、"Generated app"(App name / Repository name / Summary / Package)、
   "Description (README.md) — shown on the store page"(コミットされる README。AI が書かなければ雛形のもの)、"Files (N)"、
   "Create repository" / "Start over" と説明。
3. アプリのページ(`app-detail`、訪問者用): アイコン、名前、一言、"by <login>"、"Download APK (vX)" と
   "or install from the APSlop store app on your phone"(未公開なら "This app is not in the store yet. ...")、
   "Description (README)"、右に "Information"(Author / Version / Size / Min Android API / Updated / Package)と
   "For developers"(Source code on GitHub ↗ / Open in APSlop Developers → / 説明)。状態の印とストアへの同期ボタンはこの画面から外した。
4. PR の詳細(`pull-detail`): "<login> wants to merge N commits into main from <branch>"、レビューの印 Approved /
   Changes requested / Commented、"Files changed (N)"、変更の種類 Modified / Added / Removed。"Review" の欄に
   Comment / Approve / Request changes / "Close pull request"(作者か書き込み権限のある人)/ "Squash and merge"(書き込み権限の
   ある人)と、"Actions are performed as your GitHub account. ..."。
5. Releases(`repo-releases`): リリースのカードに APK の名前と大きさ、"Sync to store" と "Published"、"Recent CI runs"(✓ ✗ …)、
   "New release"(Tag / Title / Release notes / Create release)、"How releases work"。"New release" と "Sync to store" はアプリの
   持ち主にだけ出す。
6. エラー(`error`): "Something went wrong" と内容、"Try again"。見つからない(`not-found`): "Page not found" と "Back to apps"。
7. サーバーから返る文(ログインが必要、名前の重複、タグの形式、AI の拒否や途中切れ など)も英語にした。

### 決めたこと(見た目に出ない)

- アプリのページの説明は、公開済みならストアの説明(リリース時点の README)、未公開なら GitHub の README、どちらもなければ記録の説明。
  Size と Min Android API はストアの一覧から取る(store-server の `/apps` に `apkSize` と `minSdk` を足した)。
- 書き込み権限はサーバー用トークンで `collaborators/{login}/permission` を見て判断する(role が write / maintain / admin)。
  閉じる・マージの可否は最終的に GitHub が判断する(利用者のトークンで送る)。
- "Sync to store" はサーバー側でも持ち主に限った(他人には 404)。リリースの作成は利用者のトークンなので GitHub が判断する。
- AI への指示文(プロンプト)は日本語のまま。生成されるアプリの表示言語は変えていない。

### 受け入れで見つかった不具合(増分 5)

- 実機で APK を入れると "App not installed"。Releases のカードからは CI が作った未署名の APK しか落とせず、それは端末に入らない
  (エミュレーターで `INSTALL_PARSE_FAILED_NO_CERTIFICATES` を確認。ストアが署名した APK は入る)。カードの先頭に、ストアにある
  リリースなら署名済みの "Download APK" を出し、CI の APK は "Unsigned build:" と明記する。ストアにまだ無いときは
  "Phones cannot install the unsigned build. ..." を出す。

## 増分 6: ストアアプリ(Android)を Design B に合わせる

### 利用者から見た流れ

1. 一覧(`store-list`): 上の帯は黒地に "APSlop Store" と設定の歯車だけ(更新ボタンは外し、下に引いて更新)。
   その下に "Search apps"、"N apps"、アプリのカード(アイコン、太字の名前、"作者 · vX"、一言、"Updated <日付>")。
   検索は作者名でも当たる。何も当たらなければ "No apps match "…"" を出す。
2. 詳細(`store-detail`): 黒地の帯にアプリ名と戻る矢印。アイコン、名前、一言、"by 作者"、幅いっぱいの "Install"
   (入っていれば "Open"、古ければ "Update" と "Open")、説明(README)、Author / Version / Size / Min Android API /
   Updated / Package、幅いっぱいの "Source code on GitHub ↗"。Website ボタンは外した(多くは GitHub と同じ URL)。
3. 設定(`store-settings`): "Repository URL"、"You can add this URL to the official F-Droid client to get the same apps."、
   同じ幅の "Save and refresh" / "Reset to default"、区切り線、"APSlop Store <版>"。

### 決めたこと(見た目に出ない)

- 文言は英語だけにした(日本語の文言ファイルを英語に置き換え、英語用の別ファイルは消した)。日付は端末の言語に関わらず
  "Sep 12, 2026" の形、サイズの小数点も "."。
- 色は Web に合わせて固定した(端末の壁紙から色を取る機能は使わない)。帯 `#24292F`、主ボタン緑 `#1F883D`、コードの背景 `#F6F8FA`。
- 作者はストアのメタデータの `AuthorName`。リポジトリは Organization のものなので、web が `/sync` に持ち主の login を
  `author` として渡す(省略時は Release の作成者)。作者が無い古いアプリは "vX" だけ出し、"by" と Author の行を出さない。
